# Workflow 13.3 – Refactor Group Behaviors into Specialized AST Modules

## Objective

Refactor the group parser by introducing **specialized AST constructors** and **behavior-specific parser modules**.

This is an architectural refactor whose primary goals are:

- Reduce the complexity of `group.lua`
- Make every group behavior self-contained
- Make the AST self-documenting
- Preserve **100% parser and matcher compatibility**

No behavior, API, or test expectations should change.

---

## Goals

- Remove the giant `getGroupBehavior()` implementation.
- Give every group behavior its own parser module.
- Give every group behavior its own AST constructor.
- Make AST construction explicit instead of mutating a generic node.
- Preserve every existing parser feature.
- Preserve every existing matcher feature.

---

## Non-Goals

Do **NOT**:

- Change runtime behavior.
- Change matching semantics.
- Modify parser logic.
- Optimize performance.
- Rename AST properties.
- Change matcher implementation.
- Change tests.

This workflow is purely architectural.

## High-Level Design

Instead of constructing a generic group node and progressively mutating it,

```lua
local node = AST.Group()

node.isAtomic = true
node.disableCapture = true
...
```

each behavior should construct its own AST through a dedicated constructor.

Example:

```lua
AST.Group()
AST.GroupCapture()
AST.GroupNamed()
AST.GroupNonCapturing()
AST.GroupAtomic()
AST.GroupBranchReset()
AST.GroupLookahead()
AST.GroupLookbehind()
AST.GroupRecursion()
AST.GroupComment()
AST.GroupInlineFlags()
AST.GroupScopedFlags()
```

This makes the AST self-documenting and moves responsibility to the behavior that owns it.

---

## AST Constructors

The following constructors should exist.

```lua
AST.Group()

AST.GroupCapture()

AST.GroupNamed()

AST.GroupNonCapturing()

AST.GroupAtomic()

AST.GroupBranchReset()

AST.GroupLookahead()

AST.GroupLookbehind()

AST.GroupRecursion()

AST.GroupComment()

AST.GroupInlineFlags()

AST.GroupScopedFlags()
```

Every constructor must return:

```lua
type = "group"
```

so matcher compatibility is preserved.

---

## AST Field Contract

Every constructor must explicitly expose **every supported field**, even when unused.

Example:

```lua
{
    type = "group",

    ------------------------------------
    -- Common
    ------------------------------------

    tree = nil,

    index = nil,

    name = nil,

    hasBehavior = false,

    disableCapture = false,

    ------------------------------------
    -- Assertions
    ------------------------------------

    isLookahead = false,

    isLookbehind = false,

    isNegative = false,

    fixedLength = nil,

    ------------------------------------
    -- Atomic / Branch Reset
    ------------------------------------

    isAtomic = false,

    isBranchReset = false,

    ------------------------------------
    -- Flags
    ------------------------------------

    inlineFlags = nil,

    scopedFlags = nil,

    ------------------------------------
    -- Recursion
    ------------------------------------

    isRecursion = false,

    isRecursionRoot = false,

    targetIndex = nil,

    targetName = nil,

    ------------------------------------
    -- Internal
    ------------------------------------

    _skipFromTree = false,
}
```

Every constructor should initialize all fields.

This makes the AST fully discoverable and predictable.

## Constructor Responsibilities

### AST.Group()

Represents a regular capturing group.

Defaults:

```lua
disableCapture = false
hasBehavior = false
```

---

### AST.GroupNonCapturing()

Responsible for:

```text
(?:...)
```

Defaults:

```lua
disableCapture = true
hasBehavior = true
```

---

### AST.GroupNamed()

Responsible for:

```text
(?<name>...)
```

Owns:

```lua
name
```

---

### AST.GroupAtomic()

Responsible for:

```text
(?>...)
```

Defaults:

```lua
disableCapture = true
isAtomic = true
hasBehavior = true
```

---

### AST.GroupBranchReset()

Responsible for:

```text
(?|...)
```

Defaults:

```lua
disableCapture = true
isBranchReset = true
hasBehavior = true
```

---

### AST.GroupLookahead()

Responsible for:

```text
(?=...)
(?!...)
```

Owns:

```lua
isLookahead
isNegative
```

---

### AST.GroupLookbehind()

Responsible for:

```text
(?<=...)
(?<!...)
```

Owns:

```lua
isLookbehind
isNegative
fixedLength
```

---

### AST.GroupRecursion()

Responsible for:

```text
(?R)
(?0)
(?1)
(?123)
(?&name)
```

Owns:

```lua
isRecursion
isRecursionRoot
targetIndex
targetName
```

---

### AST.GroupComment()

Responsible for:

```text
(?#...)
```

Defaults:

```lua
disableCapture = true
_skipFromTree = true
hasBehavior = true
```

---

### AST.GroupInlineFlags()

Responsible for:

```text
(?im)
(?-i)
(?ims)
(?i-ms)
```

Owns:

```lua
inlineFlags
_skipFromTree = true
hasBehavior = true
```

---

### AST.GroupScopedFlags()

Responsible for:

```text
(?i:...)
(?-i:...)
(?ims:...)
```

Owns:

```lua
scopedFlags
disableCapture = true
hasBehavior = true
```

## Behavior Parser Modules

Every parser module should:

- Recognize only its own syntax.
- Create the appropriate AST constructor.
- Populate only the fields it owns.
- Return the completed AST node.

Behavior modules **must not** parse subtrees.

Subtree parsing remains centralized inside `Group.parse()`.

Example:

```lua
return AST.GroupAtomic()
```

instead of

```lua
local node = AST.Group()

node.isAtomic = true
node.disableCapture = true

return node
```

---

## Group.parse()

Responsibilities remain:

- Consume `(`
- Invoke the dispatcher
- Apply scoped flags
- Parse subtree
- Restore scoped flags
- Register metadata
- Validate lookbehind fixed length
- Append AST node to the tree

---

## Group.match()

No changes.

Runtime execution remains centralized.

Do **not** split matcher logic into behavior-specific modules unless it's simple and doesn't duplicate code.

---

## Coding Standards

The refactor must follow the existing project conventions.

### Enums

Avoid raw string literals or magic values.

Whenever a parser needs to identify or compare a token, behavior, or element type, create and use the appropriate enum instead.

Examples include (but are not limited to):

- Group behavior characters
- Magic tokens
- Element types
- AST types
- Parser states
- Internal behavior identifiers

Preferred:

```lua
if currentCharacter == ENUM_GROUP_ATOMIC_BEHAVIOR then
```

Avoid:

```lua
if currentCharacter == ">" then
```

The goal is to keep parsing logic consistent with the rest of the codebase and ensure all parser behavior is driven through shared enums.

### Existing Conventions

- Reuse existing enums whenever possible.
- Introduce new enums only when a concept does not already exist.
- Do not duplicate enum values across modules.
- Keep naming consistent with the existing parser architecture.

---

## Acceptance Criteria

The workflow is complete only if:

- Every existing parser test passes.
- Every matcher test passes.
- AST snapshots remain identical.
- Public API remains unchanged.
- Runtime behavior is unchanged.
- `group.lua` no longer contains the large behavior parsing implementation.
- Every group behavior owns its own AST constructor.
- Every AST constructor explicitly initializes all supported fields, even when unused.

The resulting architecture should make it immediately obvious which AST structure belongs to each group behavior while keeping parsing modular and execution centralized.
