# Workflow 12.1 — Parser Migration

All regex functionality has now been implemented.

The objective of this workflow is to complete the migration to the new parser architecture.

This is a structural workflow only.

Do not introduce new regex features or change externally observable behavior.

The Wiki remains the source of truth.

## Goals

* Complete the migration to the new parser.
* Ensure every parser consumer uses the new parser exclusively.
* Remove the legacy parser entirely.
* Improve readability, maintainability, and consistency while performing the migration.

## Tasks

Complete the migration of every remaining parser implementation, including but not limited to:

* parsing logic
* parser validation
* parser metadata generation
* parser helper functions
* parser state management
* parser consumers

Remove:

* legacy parser implementation
* obsolete parser helpers
* obsolete parser state
* dead parser code
* compatibility layers related to the parser

Hide parser implementation details behind appropriate abstractions.

Avoid exposing mutable parser internals.

Simplify parser APIs wherever possible.

## Code Quality

While modifying parser code:

* Rename variables, functions, fields, and modules to descriptive names.
* Remove ambiguous and single-character variable names except for trivial loop indices.
* Improve naming consistency throughout the parser.
* Remove redundant variables.
* Remove unnecessary temporary values.
* Simplify expressions.
* Simplify control flow.
* Reduce nesting where practical.
* Consolidate duplicated parser logic.
* Remove dead code.
* Remove obsolete comments.
* Remove outdated TODOs.
* Remove temporary debugging utilities.
* Remove tracing, logging, and diagnostic code that is no longer required.
* Add clear comments describing parser algorithms and non-obvious implementation details.
* Prefer self-documenting code over excessive comments.

## Validation

* All parser tests pass.
* Complete test suite passes.
* Matcher behavior is unchanged.
* No remaining references to the legacy parser.

## Deliverables

* New parser exclusively used.
* Legacy parser removed.
* Parser cleanup completed.

## Commit

Before committing:

* ensure the project builds
* ensure the complete test suite passes
* ensure no parser debug code remains
* ensure parser documentation reflects the migration

Create a single commit describing the completed parser migration.
