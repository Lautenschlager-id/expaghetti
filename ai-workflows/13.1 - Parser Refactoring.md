# Workflow 13.1 — Parser Refactoring

Implement the parser improvements identified during Workflow 12.3.

The objective is to leave the parser significantly simpler, cleaner, and easier to maintain while preserving identical behavior.

## Goals

Refactor the parser.

Improve readability.

Simplify implementation.

Reduce complexity.

## Engineering Standards

Every modified file should be left in a better state than before.

While working on the parser:

* improve parser algorithms
* simplify parser logic
* simplify AST construction
* simplify control flow
* split large functions
* merge duplicated logic
* reduce nesting
* improve file organization
* improve API design
* improve naming
* replace raw strings with enums where appropriate
* remove magic values
* remove redundant variables
* remove unnecessary temporary variables
* remove dead code
* remove obsolete helpers
* remove obsolete debug utilities
* add concise, meaningful comments describing parser behavior and non-obvious algorithms
* prefer self-documenting code whenever practical

Preserve the AST architecture.

Do not redesign the parser around a different execution model.

## Validation

Continuously verify:

* `cd tests && lua init.lua`
* `cd tests && lua test_matcher.lua`
* all affected tests

## Commit

Commit progress in logical batches throughout the workflow.

Each batch should build successfully and pass the relevant tests.

Create a final commit summarizing the completed parser refactoring.
