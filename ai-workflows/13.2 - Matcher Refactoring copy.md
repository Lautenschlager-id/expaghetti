# Workflow 13.2 — Matcher Refactoring

Implement the matcher improvements identified during Workflow 12.3.

The objective is to simplify the matcher implementation while preserving identical matching behavior.

## Goals

Refactor the matcher.

Improve readability.

Simplify algorithms.

Reduce complexity.

## Engineering Standards

Every modified file should be left in a better state than before.

While working on the matcher:

* simplify matching algorithms
* simplify recursion
* simplify capture handling
* simplify state flow
* simplify dispatch logic
* split large functions
* merge duplicated logic
* reduce nesting
* improve API design
* improve naming
* replace raw strings with enums where appropriate
* remove magic values
* remove redundant variables
* remove unnecessary temporary variables
* remove obsolete helper functions
* remove dead code
* remove obsolete debug utilities
* add concise, meaningful comments describing matcher behavior, recursion, captures, and backtracking
* prefer self-documenting code whenever practical

Preserve the AST architecture.

Do not redesign the matcher around a different execution model.

## Validation

Continuously verify:

* `cd tests && lua init.lua`
* `cd tests && lua test_matcher.lua`
* all affected tests

## Commit

Commit progress in logical batches throughout the workflow.

Each batch should build successfully and pass the relevant tests.

Create a final commit summarizing the completed matcher refactoring.
